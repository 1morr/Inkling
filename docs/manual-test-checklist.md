# 手動驗證清單

## 為什麼需要這份清單

Command Palette 沒有提供 UI 自動化介面,擴展又跑在獨立的 COM 進程裡,沒有辦法自動驅動
它的畫面。所以驗證分成兩半:

| | 怎麼驗 |
|---|---|
| 儲存、解析、搜索、標題/內文切分 | `dotnet test` —— 全自動,涵蓋所有非 UI 邏輯 |
| 套件有沒有真的裝上 | `tools/VerifyRegistration` 探針 —— 全自動,查 Windows 的 AppExtension 目錄 |
| 存檔結果對不對 | 直接看 `%OneDrive%\Notelet` 底下的檔案內容,可以斷言 |
| **畫面有沒有出現、按下去有沒有反應** | **只能靠眼睛,就是這份清單** |

換句話說:「行為對不對」靠測試,「長得對不對」靠這份清單。

## 每次改動後的前置動作

```powershell
.\tools\deploy.ps1 -Configuration Release -Reload
```

`-Reload` 需要先打開 CmdPal 設定 → 一般 → For developers → Enable external reload;
沒開的話腳本會提醒你,改成在 Command Palette 手動執行 **Reload**(要選副標題是
`Reload Command Palette extensions` 的那一個)。沒跑 Reload 的話 CmdPal 會繼續用舊的
擴展實例,你會以為改動沒生效。

設定頁的擴展清單出現**兩個 Notelet** 的話,再 Reload 一次就會收回一個 —— 那是 CmdPal
在套件重新註冊時多建了一個 provider,不是擴展壞掉,不必重開 PowerToys。

**每次 Reload 或重新部署之後,設定頁要關掉重開**(退回 Extensions 清單再點進來)。
那個頁面綁在舊的擴展實例上,不重開的話按 Save 會靜靜地什麼都不做 —— 驗設定相關的項目時
先做這一步,否則你驗到的是一顆死按鈕。

## 1. 擴展載入

- [ ] 叫出 Command Palette,往下捲(或按一次 `↑`)能看到 **Notelet**
- [ ] 也能看到 **Notelet:快速記下**、**Notelet:新增筆記** 與 **Notelet:刪除所有筆記**
- [ ] 圖示正常顯示,不是空白方塊

Reload 之後跑這段,確認 CmdPal 載入的是你剛部署的那一份 —— 不是某個舊佈局:

```powershell
(Get-AppxPackage -Name Notelet).InstallLocation
(Get-Process Notelet -ErrorAction SilentlyContinue).Path
```

兩者應該指向同一個資料夾。第二行沒有輸出代表 CmdPal 還沒把擴展的 COM server 拉起來,
先進一次 Notelet 頁面再看。

設好 alias 之後跑這段,確認 CmdPal 記的是我們寫死的 Id,而不是它自己拿標題算出來的雜湊
—— 這是快速記下唯一入口的生死線:

```powershell
$s = Get-Content "$env:LOCALAPPDATA\Packages\Microsoft.CommandPalette_8wekyb3d8bbwe\LocalState\settings.json" -Raw | ConvertFrom-Json
$s.Aliases.PSObject.Properties | Where-Object { $_.Value.CommandId -like 'Notelet*' } | ForEach-Object { "$($_.Name) -> $($_.Value.CommandId)" }
```

- [ ] 印出來的 CommandId 是 `Notelet.QuickCapturePage`,
      而不是 `Notelet_…!App!Notelet` 後面接一串數字

## 2. 快速記下(需求 1)

先設好入口:設定 → Extensions → Notelet → `Notelet:快速記下` → Alias 填 `n`。

- [ ] 主搜尋框打 `n` 空白 —— 搜尋框被清空,**直接進到快速記下頁**
      (indirect alias 存的鍵是「alias + 空白」,所以是打完空白那一刻觸發)
- [ ] 頁面剛進去、還沒打字時,顯示的是「打字就記下」的提示,**沒有**「記下:」那一列
- [ ] 打 `測試想法一`,第一列出現 **記下:測試想法一**,分在「記下」那一節底下
- [ ] 按 Enter,跳出「已記下」的 toast,**而且自動回到主頁**(不會留在快速記下頁)
- [ ] `%OneDrive%\Notelet` 底下出現 `<日期>-<時間>-測試想法一.md`
- [ ] 打開該檔案,front matter 的 `id` / `title` / `created` / `updated` / `tags` 都在,內文是空的
- [ ] **不吵人檢查**:主搜尋框打一般查詢(`notepad`、`note about x`、`chrome`),
      清單裡**不應該**出現任何 Notelet 的記下項目,也不應該有點不動的空列

相似筆記提醒(換成頁面才做得到的 —— fallback 只有一列):

- [ ] 再打一次 `n ` 然後輸入 `測試想法一`,「記下」那一列底下出現
      **已經記過的** 一節,列著剛才存的那則
- [ ] 按方向鍵選中既有的那則、Enter,進的是**預覽頁**而不是又存一則新的
- [ ] 剛存完一則之後立刻再打一樣的標題,新存的那則**馬上**出現在「已經記過的」裡
      (項目快取的鍵有帶 repository 的 Version,只以查詢字串為鍵的話這裡會看到舊結果)
- [ ] 打一個完全沒記過的標題,只有「記下」一列,不會有「已經記過的」那一節

分隔符切開標題與內文(以下都在快速記下頁裡打,分隔符維持預設的 `;;`):

- [ ] 頁面的 placeholder 寫的是 **打字記下想法,`;;` 後面接內文…**
- [ ] 還沒打字時那塊提示的副標是 **「買咖啡機;;比較過幾台」…**(例子用的是**真的**分隔符,
      不是單一個分號 —— 單一個分號根本不會切)
- [ ] 打 `測試想法二;;這是內文`,項目標題是 **記下:測試想法二**,副標題是 **內文:這是內文**
- [ ] Enter 之後,檔案的 `title` 是「測試想法二」,內文是「這是內文」,檔名用的是標題
- [ ] **單一個分號不切**:打 `for (var i = 0; i < 10; i++)`,整句都是標題,沒有內文
- [ ] 全形 `；；`(中文輸入法直接打出來的那個)一樣有效
- [ ] 半形全形混著打(`;；` 或 `；;`)也有效 —— 中英切換時打出哪一個並不受控
- [ ] `標題;;第一段;;第二段` 只切第一組,內文是 `第一段;;第二段`
- [ ] `標題;;`(分隔符打了、內文還沒打)照樣可以存,存出來只有標題
- [ ] `;;只有內文` 不會出現「記下:」

### 2a. 換掉分隔符(設定 → 快速記下的分隔符)

**這一段的重點是「不必 Reload」**:CmdPal 握著的是使用者當下開著的那個頁面實例,
靠 provider 重建是換不掉它的(見 README〈標題與內文用分隔符切開〉)。

- [ ] **先把快速記下頁開著**,另外從 CmdPal 設定 → Extensions → Notelet 把分隔符改成 `,,`,存檔
- [ ] 回到那個**還開著的**快速記下頁(不要 Reload、不要重進):placeholder 已經變成
      **…`,,` 後面接內文…**,空白提示的例子也換成 `買咖啡機,,比較過幾台`
- [ ] 打 `測試想法三,,這是內文` → 切得開,標題是「測試想法三」
- [ ] 打 `測試想法四;;這是內文` → **整句都是標題**,`;;` 沒有留成備援
- [ ] 全形 `，，` 一樣切得開
- [ ] 設定填成全形 `，，`、打字打半形 `,,` → 照樣切得開(設定那一頭也走同一個折算)
- [ ] 把欄位**清空**存檔 → 回到預設 `;;`,而且設定頁再打開時輸入框顯示的就是 `;;`
      (存回去的是整理過的值,不會出現「看起來設了、其實沒生效」)
- [ ] 填一個前後帶空白的值(例如 `␣->␣`)→ 空白被去掉,`標題->內文` 切得開
- [ ] 填多字元的 `-->` → `標題-->內文` 切得開;`標題--`(只打了一半)整句都是標題
- [ ] 分隔符改完之後,頂層那一列的副標仍然是 **打字直接存成筆記,分隔符後面接內文**
      (那一列跟不上設定,所以刻意不提「分號」)
- [ ] 改回 `;;` 收尾

貼上多行內容(CmdPal 搜尋框是單行的,這條是繞過它的路):

- [ ] 複製一段**多行**的 Markdown(至少三行,含一個 `#` 標題與一個清單)
- [ ] 進快速記下頁打一個標題,清單出現**第二列**「記下:<標題>」,
      副標題是 **內文取自剪貼簿(N 行)**,行數與你複製的相符
- [ ] 選那一列按 Enter,打開檔案 —— 內文是**完整的多行原文**,換行與縮排都在
- [ ] 對照第一列(普通的「記下」):它存出來的內文只有你在搜尋框裡看得到的那些字
- [ ] 剪貼簿是**單行**文字時,那一列**不該出現**(單行搜尋框自己貼得進去)
- [ ] 剪貼簿是空的、或放的是圖片時,頁面正常運作,不跳錯誤
- [ ] **不該有任何前綴判斷**:打 `note about something` 照樣出現
      「記下:note about something」—— 進得了這一頁就代表意圖明確,不該再擋一次

全域快速鍵(可選,設了就連 `n` 都省):

- [ ] 給 `Notelet:快速記下` 設一個全域快速鍵,按下去直接進頁面,打字、Enter 一樣可用

### 2b. alias 不會失效(Id 的回歸測試)

快速記下唯一的入口就是 alias,而 alias 存的鍵是命令的 `Id`。改標題不該影響它:

- [ ] 設好 alias 之後 Reload 一次,`n ` **照樣**直接進快速記下頁
- [ ] 重新部署(`deploy.ps1`)之後 alias 也還在
      (曾經有 bug:命令沒有設 `Id`,CmdPal 就拿 `ProviderId + DisplayTitle + Title + Subtitle`
      算一個雜湊當 Id。標題變一個字,使用者設過的 alias / 快速鍵 / 釘選就全部對不上。
      修法是寫死 `Id`,見 `src/Notelet/CommandIds.cs`)

## 3. 瀏覽與搜索(需求 2)

先多記幾則不同內容的筆記,再驗:

- [ ] **新增後立刻回到清單,新筆記就在裡面**(曾經有 bug:清單頁的項目快取只以查詢字串
      為鍵,新增之後回來拿到的還是舊結果,畫面顯示「還沒有任何筆記」。
      修法是把 repository 的 `Version` 一起納入快取的鍵)
- [ ] 進入 Notelet,列出所有筆記,最新的在最上面
- [ ] 右側詳細窗格顯示該則筆記的內容
- [ ] 輸入標題裡的關鍵字,能找到
- [ ] 輸入**只出現在內文**的關鍵字,也能找到
- [ ] 輸入兩個關鍵字(空白隔開),只留下兩個都命中的
- [ ] 全形空白隔開的兩個關鍵字也有效(中文輸入法很容易打出全形空白)
- [ ] 大小寫不敏感(用英文筆記測 `docker` / `DOCKER`)
- [ ] 標題命中的排在只有內文命中的前面
- [ ] **手感檢查**:連續快速輸入,清單跟得上,沒有可感的延遲或卡頓
- [ ] 一則筆記都沒有時,顯示的是「還沒有任何筆記」的提示而不是空白

## 4. 原始文字切換(`Ctrl+U`)

在清單頁選中一則**有格式的**筆記(至少含一個 `#` 標題與一段 `**粗體**`):

- [ ] 按 `Ctrl+U`,右側窗格從渲染結果變成原始 Markdown,`#` 與 `**` 都看得到
- [ ] **選中的項目沒有跳掉**,還是原本那一則(這是這個功能的重點:實作是換掉
      `ListItem.Details` 而不是 `RaiseItemsChanged`,清單本身完全不動)
- [ ] **按下去就要變**,不需要離開再重進清單頁(曾經有 bug:改的是 `Details.Body`,
      而 `IDetails` 沒宣告成可觀察介面,那個通知跨不過 out-of-process 邊界,
      表現出來就是「值改了、畫面不動」)
- [ ] 再按一次 `Ctrl+U` 切回渲染結果
- [ ] `Ctrl+K` 打開選單,那一項的字會跟著狀態變(「顯示原始文字」↔「顯示渲染後的預覽」)
- [ ] 在原始文字模式下,用滑鼠拖曳選取窗格裡的一段文字並 `Ctrl+C`,貼出來與檔案內容一致
      (若 CmdPal 的 Markdown 控件不支援選取,記在下面的「記錄」裡 —— 那是控件的限制,
      不是這個功能沒生效)
- [ ] 切到原始文字模式後再打字搜索,清單換了但仍然停在原始文字模式
- [ ] 切換後上下移動選中項,其他筆記也是原始文字模式
- [ ] 原始文字模式**沒有外框、沒有底色**,字體與其他內容一致,跟著窗格寬度自然換行
- [ ] 內文**本身含有程式碼區塊**的筆記,在原始文字模式下整則都還是純文字,
      連 ``` 那三個反引號本身都看得到,不會有任何一段被渲染成別的樣子
- [ ] 沒有內文的筆記顯示「(沒有內文)」,兩個模式都不會出錯

## 5. 詳細面板寬度(`Ctrl+D`)

在清單頁選中一則內文夠長的筆記:

- [ ] 按 `Ctrl+D`,右側窗格明顯變寬(窄 → 中),清單那一側相應變窄
- [ ] 再按一次變成最寬(中 → 寬),清單與詳情大約各佔一半
- [ ] 第三次按回到最窄,循環正確
- [ ] **選中的項目沒有跳掉**,理由跟 `Ctrl+U` 同一條:換的是 `ListItem.Details`,清單不動
- [ ] **按下去就要變**,不需要離開再重進清單頁
- [ ] `Ctrl+K` 打開選單,那一項的字會跟著狀態變(「詳細面板加寬(中)」→「…(寬)」→
      「詳細面板縮回最窄」)
- [ ] 寬度與 `Ctrl+U` 互不干擾:在原始文字模式下調寬度,仍然是原始文字;調完寬度按
      `Ctrl+U` 也仍然是剛才那個寬度
- [ ] 打字搜索、上下移動選中項,寬度都保持不變
- [ ] **調完寬度離開 CmdPal 再回來(或 Reload、甚至重開機),寬度還是剛才那一檔**
- [ ] 設定頁的「詳細面板寬度」顯示的就是剛才 `Ctrl+D` 選到的那一檔

反過來從設定頁改(**曾經壞掉,不要略過**):

- [ ] 清單頁開著 → 去設定頁把寬度改成別的檔位 → Save → 回清單頁,
      **不必 Reload 就是新的寬度**
      (壞掉時的症狀:改了要 Reload 才生效。原因不是沒存檔 —— log 顯示 `SaveSettings`
      跟 `BuildState` 都跑了。是 CmdPal 手上握著的還是**舊的頁面實例**,新建的那個
      它根本不會去拿,而舊實例的項目快取查詢與 Version 都沒變,就把舊寬度一路留著。
      修法是讓現有頁面自己響應 `DetailsWidthChanged`,不靠整組重建)
- [ ] 接著在清單頁按 `Ctrl+D`,`Ctrl+K` 選單上的字是從**設定頁那一檔**接下去循環的,
      不是從舊值(兩邊改的是同一個值,選單文字也得跟上)

反過來從 `Ctrl+D` 改(**也曾經壞掉,而且要驗兩個入口**):

設定頁有兩個入口,曾經只有第一個是對的 —— 見 README〈設定頁有兩個入口〉。

- [ ] 清單頁按 `Ctrl+D` 換一檔 → `Ctrl+K` → 設定 → **下拉選單顯示的就是剛才那一檔**
- [ ] **再驗另一個入口**:設定 → Extensions → Notelet → 那一頁的下拉選單
      **也是剛才那一檔**
      (壞掉時的症狀:這一個停在「開啟 CmdPal 時」的值,不管改幾次都不動,
      連 Reload 都未必救得回來。`ProviderSettingsViewModel` 用
      `_initializeSettingsTask ??=` 只初始化一次,而它拿的是 `ICommandSettings.SettingsPage`。
      修法是自己實作 `ICommandSettings`,把我們的頁面交出去)
- [ ] 兩個入口顯示的值**永遠一致**(它們是同一個頁面實例)
- [ ] 在那個設定頁直接按 Save(不改任何東西),清單頁的寬度**不會跳掉**
- [ ] **焦點不會被搶**:設定視窗開在背景 → 回主視窗按 `Ctrl+D` → 焦點**留在主視窗**,
      設定頁的下拉選單仍然跟著變
      (壞掉時的症狀:每按一次 Ctrl+D,背景的設定視窗就跳到前面來。
      `ContentFormControl` 載入後會自動聚焦,而我們每次都得叫它重讀表單 = 重建 + Loaded。
      靠表單後面那塊空白內容讓 `OnlyControlOnPage` 變成 false 才擋掉 ——
      **那塊空白是承重牆,不要當成忘了刪的東西清掉**,見 README)
- [ ] 設定頁上看不到多餘的空白區塊,說明文字全部貼在自己的欄位底下
- [ ] 對照組:`Notelet:新增筆記` 的表單**游標仍然自動落在標題框**(它只有一塊內容,不受影響)

## 6. Markdown 預覽(需求 3)

先建一則內文含各種語法的筆記(可以直接用編輯器寫進檔案):

```markdown
## 二級標題

- 清單項目一
- 清單項目二

| 欄位 | 值 |
|---|---|
| a | 1 |

`行內程式碼` 與 **粗體**

\`\`\`csharp
var x = 1;
\`\`\`

[連結](https://example.com)
```

- [ ] 選中該筆記按 Enter,進入預覽頁
- [ ] 標題渲染成 H1,而且**沒有重複出現兩次**
- [ ] 二級標題、清單、表格、程式碼區塊、粗體、連結都正確渲染
- [ ] **打三行看到三行**:內文打 `111` / `222` / `333` 三行,預覽顯示三行而不是
      `111 222 333`(標準 Markdown 會併成一行,Notelet 只在渲染時把單換行當成換行,
      磁碟上的檔案不變)
- [ ] 程式碼區塊裡的內容**沒有**被加上多餘的行尾空白(用「在預設編輯器開啟」對照原檔)
- [ ] 清單頁右側詳細窗格的換行行為跟預覽頁一致
- [ ] `Ctrl+K` 能看到「編輯」與「在預設編輯器開啟」
- [ ] 「在預設編輯器開啟」真的用系統預設程式打開了那個 `.md`
- [ ] 「複製內文」之後貼上,內容正確

## 7. 編輯(需求 4)

- [ ] 在清單選中一則筆記,`Ctrl+E` 進入編輯表單

## 9. 設定

- [ ] 在 Notelet 上按 `Ctrl+K` → 設定,設定頁打開
- [ ] 有三個設定項,由上到下:筆記資料夾、快速記下的分隔符、詳細面板寬度
      (`QuickCaptureEnabled` / `QuickCapturePrefix` 已經隨 fallback 一起移除。
      舊的 settings.json 裡可能還留著這兩個鍵,是孤兒,會被忽略;
      分隔符那個鍵舊檔案裡也不會有,讀不到就當預設值)

- [ ] 分隔符的說明裡**看不到反引號**(Adaptive Cards 的 `TextBlock` 不認得它,
      會照字面印出來 —— 所以那段字用的是「」)
- [ ] 寬度下拉選單**沒有撐滿整頁**,三個設定項之間都有分隔線
- [ ] 把資料夾改到另一個路徑,清單改讀新資料夾,新筆記寫進新資料夾
- [ ] 改完設定之後 `Notelet:快速記下` 照樣能用(整組 provider 會重建,頁面是新的那一個)
- [ ] 在資料夾輸入框裡按 Enter = 存檔(**不是**跳出瀏覽對話框)

### 9b. 「瀏覽…」按鈕

- [ ] 「瀏覽…」跟輸入框排在同一列,高度對齊
- [ ] 按下去跳出系統的選資料夾對話框,**開在最上面看得到**
      (**這一項最重要**:對話框掛在隱藏的 owner 底下,工作列上沒有它的按鈕 ——
      萬一它開在 CmdPal 後面,使用者等於完全找不到。拉不到前景是 Windows 的前景權限限制,
      見 README〈資料夾旁邊的「瀏覽…」〉)
- [ ] 工作列上**不會多出一個空白圖示的按鈕**
- [ ] 對話框一開始停在**目前設定的那個資料夾**
- [ ] 選一個資料夾按確定 → 跳出 toast「筆記資料夾:…」,**不必再按儲存**
      (CmdPal 主視窗這時多半已經自己藏起來了 —— 失焦就隱藏是它的行為,沒有開關)
- [ ] **壓在表單上的其他改動也一起存下來了**:先把分隔符改成 `,,`(不要按儲存)、
      直接按「瀏覽…」選一個資料夾 → 分隔符也變成 `,,` 了。表單會跟著主視窗一起消失,
      那些值只有這一次機會存下來(改回 `;;` 與原本的資料夾收尾)
- [ ] 重新叫出 CmdPal → 設定頁 → 輸入框顯示的是剛才選的路徑
- [ ] 清單頁列的是新資料夾裡的筆記
- [ ] 按取消 → 什麼都不變,設定檔沒有被改寫
- [ ] 兩個入口都要驗(`Ctrl+K` → 設定,以及設定 → Extensions → Notelet)
