# 手動驗證清單

## 為什麼需要這份清單

Command Palette 沒有提供 UI 自動化介面,擴展又跑在獨立的 COM 進程裡,沒有辦法自動驅動
它的畫面。所以驗證分成兩半:

| | 怎麼驗 |
|---|---|
| 儲存、解析、搜索、前綴判斷 | `dotnet test` —— 全自動,涵蓋所有非 UI 邏輯 |
| 套件有沒有真的裝上 | `tools/VerifyRegistration` 探針 —— 全自動,查 Windows 的 AppExtension 目錄 |
| 存檔結果對不對 | 直接看 `%OneDrive%\Notelet` 底下的檔案內容,可以斷言 |
| **畫面有沒有出現、按下去有沒有反應** | **只能靠眼睛,就是這份清單** |

換句話說:「行為對不對」靠測試,「長得對不對」靠這份清單。

## 每次改動後的前置動作

```powershell
.\tools\deploy.ps1 -Configuration Release
```

然後在 Command Palette 執行 **Reload**,要選副標題是
`Reload Command Palette extensions` 的那一個。沒跑 Reload 的話 CmdPal 會繼續用舊的
擴展實例,你會以為改動沒生效。

---

## 1. 擴展載入

- [ ] 叫出 Command Palette,往下捲(或按一次 `↑`)能看到 **Notelet**
- [ ] 也能看到 **Notelet:新增筆記**
- [ ] 圖示正常顯示,不是空白方塊

Reload 之後跑這段,確認 CmdPal 載入的是你剛部署的那一份 —— 不是某個舊佈局:

```powershell
(Get-AppxPackage -Name Notelet).InstallLocation
(Get-Process Notelet -ErrorAction SilentlyContinue).Path
```

兩者應該指向同一個資料夾。第二行沒有輸出代表 CmdPal 還沒把擴展的 COM server 拉起來,
先進一次 Notelet 頁面再看。

## 2. 快速新增(需求 1)

- [ ] 在主搜尋框打 `n 測試想法一`,清單出現 **記下:測試想法一**
- [ ] 按 Enter,跳出「已記下」的 toast
- [ ] `%OneDrive%\Notelet` 底下出現 `<日期>-<時間>-測試想法一.md`
- [ ] 打開該檔案,front matter 的 `id` / `title` / `created` / `updated` / `tags` 都在,內文是空的
- [ ] **排序檢查**:打 `n ` 加字的時候,「記下:…」有沒有排在清單第一個?
      如果被其他擴展壓在下面,「打字→Enter」就不成立,要回報
- [ ] **不吵人檢查**:打一般查詢(例如 `notepad`、`note about x`、`chrome`),
      清單裡**不應該**出現 Notelet 的快速新增項目
- [ ] 只打 `n ` 不打內容時,不應該出現「記下:」

## 3. 瀏覽與搜索(需求 2)

先多記幾則不同內容的筆記,再驗:

- [ ] **新增後立刻回到清單,新筆記就在裡面**(曾經有 bug:清單頁的項目快取只以查詢字串
      為鍵,新增之後回來拿到的還是舊結果,畫面顯示「還沒有任何筆記」。
      修法是把 repository 的 `Version` 一起納入快取的鍵)
- [ ] 進入 Notelet,列出所有筆記,最新的在最上面
- [ ] 右側詳細窗格顯示該則筆記的內容
- [ ] 輸入標題裡的關鍵字,能找到
- [ ] 輸入**只出現在內文**的關鍵字,也能找到
- [ ] 輸入兩個關鍵字(空白隔開),只留下兩個都命中的
- [ ] 全形空白隔開的兩個關鍵字也有效(中文輸入法很容易打出全形空白)
- [ ] 大小寫不敏感(用英文筆記測 `docker` / `DOCKER`)
- [ ] 標題命中的排在只有內文命中的前面
- [ ] **手感檢查**:連續快速輸入,清單跟得上,沒有可感的延遲或卡頓
- [ ] 一則筆記都沒有時,顯示的是「還沒有任何筆記」的提示而不是空白

## 4. Markdown 預覽(需求 3)

先建一則內文含各種語法的筆記(可以直接用編輯器寫進檔案):

```markdown
## 二級標題

- 清單項目一
- 清單項目二

| 欄位 | 值 |
|---|---|
| a | 1 |

`行內程式碼` 與 **粗體**

\`\`\`csharp
var x = 1;
\`\`\`

[連結](https://example.com)
```

- [ ] 選中該筆記按 Enter,進入預覽頁
- [ ] 標題渲染成 H1,而且**沒有重複出現兩次**
- [ ] 二級標題、清單、表格、程式碼區塊、粗體、連結都正確渲染
- [ ] **打三行看到三行**:內文打 `111` / `222` / `333` 三行,預覽顯示三行而不是
      `111 222 333`(標準 Markdown 會併成一行,Notelet 只在渲染時把單換行當成換行,
      磁碟上的檔案不變)
- [ ] 程式碼區塊裡的內容**沒有**被加上多餘的行尾空白(用「在預設編輯器開啟」對照原檔)
- [ ] 清單頁右側詳細窗格的換行行為跟預覽頁一致
- [ ] `Ctrl+K` 能看到「編輯」與「在預設編輯器開啟」
- [ ] 「在預設編輯器開啟」真的用系統預設程式打開了那個 `.md`
- [ ] 「複製內文」之後貼上,內容正確

## 5. 編輯(需求 4)

- [ ] 在清單選中一則筆記,`Ctrl+E` 進入編輯表單
- [ ] 表單帶出目前的標題與內文
- [ ] 內文欄位是多行輸入框,不是單行
- [ ] 改完按「儲存」,跳出「已儲存」的 toast 並回到上一頁
- [ ] **回到預覽頁後,看到的是剛改完的內容**(曾經有 bug:CmdPal 不會因為導覽回上一頁
      就重新呼叫 `GetContent()`,畫面會停在存檔前的樣子。修法是存檔後由表單回呼預覽頁的
      `RaiseItemsChanged`)
- [ ] 從清單按 `Ctrl+E` 編輯並儲存,回到清單時標題與摘要也已更新
- [ ] 檔案內容確實更新,`updated` 時間戳有變,`id` 與 `created` **沒有**變
- [ ] **檔名沒有跟著標題改變**
- [ ] 把標題清空後儲存,會被擋下來並提示

**不吃掉別人的欄位**(這條最重要):

- [ ] 用文字編輯器在某則筆記的 front matter 手動加上:
      ```yaml
      cssclass: reading
      aliases:
        - 別名一
      ```
- [ ] 回到 Notelet 編輯這則筆記並儲存
- [ ] 重新打開檔案,`cssclass` 與 `aliases` **仍然在**

## 6. 新增(完整表單)

- [ ] 執行 `Notelet:新增筆記`,出現空白表單
- [ ] 填標題與多行內文並儲存,回到首頁並跳出 toast
- [ ] 檔案內容正確,內文的換行有保留

## 7. 設定

- [ ] 在 Notelet 上按 `Ctrl+K` → 設定,設定頁打開
- [ ] 三個設定項都在:筆記資料夾、啟用快速新增、快速新增前綴
- [ ] 把前綴改成 `,`,主搜尋框打 `,一個想法` 能觸發快速新增
- [ ] 關掉「啟用快速新增」,主搜尋框打 `n 東西` 不再出現快速新增
- [ ] 把資料夾改到另一個路徑,清單改讀新資料夾,新筆記寫進新資料夾

## 8. 外來檔案與同步

- [ ] 用文字編輯器在筆記資料夾放一個**沒有 front matter** 的 `.md`
      (第一行寫 `# 外面來的標題`)
- [ ] 它出現在 Notelet 清單裡,標題是「外面來的標題」
- [ ] 在子資料夾裡放一個 `.md`,它也出現在清單裡
- [ ] **即時更新**:Notelet 清單開著的時候,用編輯器改某則筆記的標題並存檔,
      清單在一兩秒內自己更新(這就是別台機器經 OneDrive 同步下來時會發生的事)

## 9. 錯誤處理

- [ ] 把設定裡的資料夾改成一個不存在的路徑,擴展不會壞掉,顯示空清單
- [ ] 在筆記資料夾放一個內容是亂碼、front matter 沒收尾的 `.md`,
      清單照樣列出其他筆記,不會整個掛掉
